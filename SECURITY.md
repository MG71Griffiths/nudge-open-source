# Security reporting

Do not put passwords, tokens, personal diaries, photos, provisioning files or an exploitable vulnerability in a public issue.

For the published GitHub repository, use **Security → Report a vulnerability** for a private report to the maintainer, Stephanie Griffiths. Include the affected release, a minimal synthetic reproduction, impact and relevant logs with credentials and personal content removed. Private vulnerability reporting must be enabled before the source repository is launched; no monitored response-time promise is made here.

If the private reporting option is absent, use the monitored support contact shown by the official app's support page to request a private reporting channel before sending sensitive details. No unverified email address is supplied here.

Only test systems and accounts you are authorised to use. The source export defaults to unconfigured service origins so local checks do not call the original operator's infrastructure.
